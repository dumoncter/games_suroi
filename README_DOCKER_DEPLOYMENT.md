# Развертывание Suroi в Railway (Docker)

## Архитектура развертывания

Проект использует два отдельных Docker контейнера в Railway:

### 🚀 Сервисы
1. **suroi-solo** (порт 8082) - соло-сервер для одиночных боев
2. **suroi-team** (порт 8083) - командный сервер для групповых боев

### 🐳 Docker конфигурация

#### Переменные окружения для каждого сервиса:
- **suroi-solo**:
  - `SERVER_TYPE=solo`
  - `PORT=8082`
  - `NODE_ENV=production`

- **suroi-team**:
  - `SERVER_TYPE=team`
  - `PORT=8083`
  - `NODE_ENV=production`

#### Автоматический выбор конфигурации:
В зависимости от `SERVER_TYPE`, Docker контейнер:
1. Выбирает правильный конфигурационный файл (`config.solo.json` или `config.team.json`)
2. Запускает сервер на указанном порту
3. Настраивает NGINX для проксирования запросов

## Процесс развертывания

### 1. Подготовка
```bash
# Убедитесь что все зависимости установлены
pnpm install

# Соберите проект
pnpm build
```

### 2. Railway.toml
Файл `railway.toml` определяет два сервиса:
```toml
[services.suroi-solo]
# Solo сервер на порту 8082

[services.suroi-team]
# Team сервер на порту 8083
```

### 3. Автоматическое развертывание
При пуше в ветку production, Railway:
1. Создает два отдельных Docker контейнера
2. Устанавливает переменные окружения для каждого
3. Запускает соответствующие серверы
4. Настраивает домены и прокси

## Структура файлов

```
suroi/
├── Dockerfile                    # Docker образ
├── railway.toml                  # Конфигурация Railway
├── scripts/start-production.js   # Скрипт запуска (выбирает тип сервера)
├── server/
│   ├── config.solo.json         # Конфиг соло-сервера
│   └── config.team.json         # Конфиг командного сервера
└── nginx.conf                    # NGINX конфигурация
```

## Мониторинг

### Health Checks
- Каждый контейнер имеет health check на `/health`
- Railway автоматически перезапускает неработающие контейнеры
- Логи доступны в Railway dashboard

### Логи
- NGINX логи: `/var/log/nginx/`
- Node.js логи: stdout/stderr
- Railway собирает все логи автоматически

## Масштабирование

### Добавление нового типа сервера:
1. Создайте `server/config.{type}.json`
2. Добавьте сервис в `railway.toml`
3. Обновите `nginx.conf` для маршрутизации
4. Обновите клиентскую конфигурацию

### Пример для "Arena" режима:
```toml
[services.suroi-arena]
# Arena сервер на порту 8084

[services.suroi-arena.env]
SERVER_TYPE = "arena"
PORT = "8084"
```

## Устранение неисправностей

### Проблемы с портами:
- Убедитесь что переменная `PORT` установлена правильно
- Проверьте что порты не конфликтуют

### Проблемы с конфигурацией:
- Проверьте переменную `SERVER_TYPE`
- Убедитесь что соответствующий `config.{type}.json` существует

### Проблемы с NGINX:
- Проверьте логи NGINX
- Убедитесь что upstream серверы доступны

## Домены и прокси

Railway автоматически:
- Создает субдомены для каждого сервиса
- Настраивает SSL сертификаты
- Проксирует запросы к контейнерам

Пример URL:
- Solo: `https://suroi-solo.neonpsh.games`
- Team: `https://suroi-team.neonpsh.games`
